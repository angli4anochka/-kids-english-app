# Отчёт по соответствию 152-ФЗ — UniPlay Kids
> Версия 1.0 · Дата: 2026-06-25

## 1. Что было найдено в ходе аудита

### Формы, собирающие персональные данные (до исправлений)
| Форма | Данные | Был чекбокс до |
|---|---|---|
| Регистрация учителя `/register` | Имя, email, пароль | ❌ Нет |
| Вход учителя `/login` | Email, пароль | ❌ Нет |
| Создание ученика (TeacherGroups) | Имя, логин, пароль | ❌ Нет |
| Импорт из TutorsDesk | Имена учеников | ❌ Нет |

### Найденные риски
1. Нет правовых страниц (политика, согласие, cookies, оферта)
2. Нет cookie banner
3. Нет footer со ссылками на документы
4. Нет механизма хранения согласий
5. Нет возможности отозвать согласие / удалить аккаунт
6. Google Fonts — трансграничная передача IP/UA
7. Google OAuth — трансграничная передача данных в США
8. Токены авторизации — Base64 (не JWT, подделываемые)
9. CORS открыт для всех Origins
10. Все API-эндпоинты публичны (нет middleware авторизации)
11. Лидерборд показывает имена учеников без согласия

## 6. Оставшиеся риски (требуют доработки)

### Высокий приоритет
- [ ] **Токены авторизации** — заменить Base64 на JWT (HS256)
- [ ] **CORS** — ограничить разрешёнными Origin
- [ ] **API авторизация** — добавить middleware проверки токенов на все эндпоинты
- [ ] **Пароль БД** — сменить `postgres:postgres` в production
- [ ] **Google OAuth** — добавить явное уведомление о передаче данных Google
- [ ] **Лидерборд** — добавить согласие `public_profile` или анонимизацию

### Средний приоритет
- [ ] **Google Fonts** — перейти на self-hosted шрифты
- [ ] **Plaintext пароли учеников** — backend не должен возвращать `plain_password`
- [ ] **robots.txt** — создать для контроля индексации
- [ ] **Rate limiting** — добавить на формы авторизации
- [ ] **Helmet.js** — добавить HTTP security headers

### Низкий приоритет
- [ ] Форма создания учеников — добавить информирование учителя об ответственности
- [ ] Механизм уведомления при изменении документов (email или баннер)
